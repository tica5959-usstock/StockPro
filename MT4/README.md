# StockPro Scalper (MT4 EA)

GOLD# / USDJPY# 대상 **추세필터 + 모멘텀 눌림목 스캘핑 EA**.
상위 타임프레임(H1)이 방향을 정하고, 하위 타임프레임(M5~M15)의 오실레이터가 진입 타이밍만 담당하는 구조입니다.
오실레이터로 역추세를 베팅하지 않기 때문에, 스캘핑이면서도 추세와 싸우지 않습니다.

---

## 설치

1. MT4 → `파일` → `데이터 폴더 열기`
2. `MQL4/Experts/` 에 `StockPro_Scalper.mq4` 복사
3. MT4 → `MetaEditor(F4)` → 해당 파일 열고 **컴파일(F7)**
4. MT4 재시작 또는 `내비게이터` 우클릭 → `새로고침`
5. GOLD# 차트(M5)와 USDJPY# 차트(M5)에 각각 드래그해서 부착
6. 설정창 → `불러오기` → `presets/GOLD.set` 또는 `presets/USDJPY.set` 선택
7. 툴바의 **자동매매(AutoTrading)** 버튼 ON

> **중요**: 차트마다 `InpMagicNumber`를 다르게 설정하세요. 같은 매직넘버를 쓰면
> 두 EA가 서로의 포지션을 자기 것으로 오인해 통계와 포지션 관리가 뒤섞입니다.
> 프리셋에는 이미 다른 값(GOLD 20260801 / USDJPY 20260802)이 들어 있습니다.

## 전략 구조

```
[H1] 추세 필터        EMA50 vs EMA200 배열  +  ADX > 임계값
        ↓ 방향 확정 (없으면 거래 안 함)
[M5]  진입 트리거     추세 방향으로 RSI/Stoch가 눌림목에서 복귀하는 순간
        ↓
      리스크 기반 랏 계산 (ATR 손절폭 기준, 계좌의 N%)
        ↓
      청산 (모드 선택)
```

### 진입 조건

| 추세 | 트리거 (RSI 모드) | 트리거 (Stoch 모드) |
|---|---|---|
| 상승 | RSI가 `InpRsiBuyLevel` 아래로 갔다가 **위로 복귀** → 매수 | 과매도 구간에서 %K가 %D **상향 돌파** → 매수 |
| 하락 | RSI가 `InpRsiSellLevel` 위로 갔다가 **아래로 복귀** → 매도 | 과매수 구간에서 %K가 %D **하향 돌파** → 매도 |

`InpSignalOnBarClose=true`(기본)면 봉 마감 후에만 판단해 리페인트를 방지합니다.

## 청산 모드 (`InpExitMode`)

입력변수로 세 가지 중 선택합니다.

### 0. 고정 TP (`EXIT_FIXED_TP`)
진입 시 SL/TP를 걸어두고 트레일링을 하지 않습니다. 결과가 SL 또는 TP 둘 중 하나로 깔끔하게 갈리기 때문에
**백테스트로 전략의 순수 기댓값을 측정할 때 기준선**으로 쓰기 좋습니다.

### 1. 트레일링 (`EXIT_TRAILING`)
TP를 걸지 않고 ATR 기반 트레일링만 사용합니다. 추세가 뻗는 날의 수익을 끝까지 가져가지만,
M5 금(GOLD#)처럼 윅이 험한 시장에서는 노이즈에 자주 털려 **평균 수익이 얇아질 수 있습니다.**

### 2. 부분청산 + 러너 트레일링 (`EXIT_PARTIAL_RUNNER`) — 기본값/권장
1. `InpPartialTriggerR`(기본 1.0R) 도달 시 물량의 `InpPartialPct`(기본 60%)를 청산
2. 잔여분("러너")의 **TP를 제거**하고 SL을 브레이크이븐으로 이동
3. 러너만 넓은 ATR 트레일링으로 추세를 따라감

대부분의 거래가 일정하게 익절되어 자금곡선이 안정되고, 가끔 나오는 추세 구간에서만 수익이 확장됩니다.

> **러너의 TP를 제거하는 이유** (`InpRunnerClearTP`, 기본 true)
> TP를 남겨두면 트레일링이 **TP 직전 좁은 구간에서만** 동작해 사실상 무의미해집니다.
> 상단을 트레일링이 결정하게 해야 추세 구간의 수익 확장이라는 목적이 살아납니다.
> TP를 유지하고 싶다면 `InpRunnerClearTP=false`로 두세요 (승률↑ / 평균수익↓).

> **파라미터 제약**: 이 모드에서는 `InpTpRR > InpPartialTriggerR` 이어야 합니다.
> 반대면 부분청산이 발동하기 전에 TP가 먼저 체결됩니다. EA가 시작 시 검사해 거부합니다.

> **자동 폴백**: 계산된 랏이 최소랏의 2배 미만이면 물량을 쪼갤 수 없습니다.
> 이 경우 해당 포지션은 **고정 TP 방식을 그대로 유지**하며(트레일링 대상에서 제외),
> 대시보드 `청산 모드` 항목에 `(폴백)`을 표시합니다.

## 왜 승률이 아니라 기댓값을 봐야 하는가

트레일링은 **승률을 올리는 대신 평균 수익을 깎습니다.** 두 항이 반대로 움직이므로 승률만으로는 판단이 안 됩니다.

```
기댓값 = (승률 × 평균수익) − (패률 × 평균손실)
```

| | 고정 TP | 트레일링 (노이즈에 자주 털릴 때) |
|---|---|---|
| 승률 | 45% | **70%** |
| 기댓값 | **+0.125R** | +0.0225R |

승률은 크게 좋아 보이는데 기댓값은 1/5로 줄어든 상태입니다. 하루 수십 회 거래하는 스캘핑에서는
거래당 비용(스프레드+커미션)이 매번 차감되므로, 이 수준까지 얇아지면 비용만으로 마이너스로 넘어갑니다.

**대시보드에서 승률보다 `기댓값(R)`과 `Profit Factor`를 먼저 보세요.**

## 리스크 관리

| 항목 | 입력변수 | 기본 | 설명 |
|---|---|---|---|
| 거래당 리스크 | `InpRiskPercent` | 0.3~0.5% | 거래 빈도가 높을수록 낮춰야 총 리스크가 관리됨 |
| 손절폭 | `InpSlAtrMult` | ATR × 1.3~1.8 | 고정 포인트가 아닌 변동성 비례 |
| 일일 손실 한도 | `InpDailyLossPct` | 3% | 도달 시 당일 신규 진입 중단 |
| 연속 손절 차단 | `InpMaxConsecLoss` | 4회 | 도달 시 `InpCooldownMin` 분간 쿨다운 |
| 동시 포지션 | `InpMaxPositions` | 1 | 신호 남발로 물량 쌓이는 것 방지 |

랏 계산식:

```
랏 = (계좌잔고 × 리스크%) / (손절거리 ÷ TickSize × TickValue)
```

**400:1 레버리지는 증거금 여유로만 활용하고, 랏수 산정 근거로 쓰지 않습니다.**
레버리지 기준으로 랏을 잡으면 한 번의 손절로 계좌가 크게 훼손됩니다.

### 최소 계좌 규모

리스크 % 방식은 계산된 랏이 최소랏(보통 0.01)에 미달하면 진입을 **건너뜁니다**(로그에 사유 출력).
거래당 0.4% 기준으로 GOLD#는 대략 **$5,000 이상**은 되어야 정상 작동합니다.

- 계좌가 그보다 작다면: `InpRiskPercent`를 올리거나, `InpAllowMinLotUp=true`로 최소랏 진입을 허용
- 단, `InpAllowMinLotUp=true`는 **설정한 리스크 %를 초과**하게 되므로 그 사실을 알고 쓰세요 (로그에 경고 출력)

## 대시보드

반투명 패널에 실시간 상태를 표시합니다. 1초마다 갱신되며, 헤더 우측의 `▲` 버튼으로 접었다 펼 수 있습니다.

| 섹션 | 표시 항목 |
|---|---|
| **계좌** | 잔고, 순자산, 증거금 사용률 (30% 초과 시 경고색) |
| **오늘** | 거래 횟수, 실현 손익(금액/%), 일일 손실한도 잔여 |
| **현재 포지션** | 매수 랏·건수, 매도 랏·건수, 순노출, 평가 손익 |
| **누적 성과** | 총 거래, 승/패, 승률, 누적 손익, Profit Factor, 기댓값(R), MDD |
| **신호·상태** | 추세 방향·ADX, 오실레이터 값, 스프레드 통과 여부, 청산 모드, 연속 손절, EA 상태 |

통계는 **해당 매직넘버 + 해당 심볼**의 거래 이력에서 매번 재계산하므로, EA를 재시작해도 값이 유지됩니다.
MDD는 청산 시각순으로 정렬한 손익 곡선에서 산출한 최대 낙폭입니다.

### 표시 설정

| 입력변수 | 설명 |
|---|---|
| `InpDashCorner` | 4개 모서리 중 위치 선택 |
| `InpDashX` / `InpDashY` | 모서리로부터의 여백 (px) |
| `InpDashWidth` | 패널 폭 (기본 268px) |
| `InpDashOpacity` | 0(투명) ~ 100(불투명), 기본 78 |
| `InpDashFont` / `InpDashFontSize` | 폰트·크기 (기본 맑은 고딕 9pt) |

> **투명도에 대한 참고**: MT4는 차트 오브젝트의 알파 채널을 지원하지 않습니다.
> 따라서 `InpDashOpacity`는 **패널색을 차트 배경색 쪽으로 섞어(blend) 반투명처럼 보이게** 하는 방식입니다.
> 차트 배경색을 읽어와 계산하므로 밝은 테마·어두운 테마 양쪽에서 자연스럽게 어울립니다.
> 다만 패널 뒤의 캔들이 실제로 비쳐 보이지는 않습니다 (MT4 자체의 제약).

폰트는 한글 라벨이 있어 **한글 글리프를 가진 폰트**여야 합니다(맑은 고딕, 나눔고딕 등).
`Consolas` 같은 영문 전용 폰트를 지정하면 한글이 깨집니다. 숫자는 우측 정렬로 자릿수를 맞췄기 때문에
고정폭 폰트가 아니어도 세로로 가지런히 읽힙니다.

## 백테스트 · 최적화

**[BACKTEST.md](BACKTEST.md)** 에 별도로 정리했습니다. 요약하면:

- M5 스캘핑은 **99% 모델링 실제 틱 데이터**가 아니면 결과 자체가 무의미합니다
- MT4 테스터는 **커미션을 반영하지 않습니다** — 수동 차감 필요
- 최적화 기준은 **`Custom max`** 를 쓰세요. EA에 `OnTester()`가 내장되어 있어
  SQN(표본수·일관성·낙폭 반영) 기반으로 평가합니다. 기본값인 `Balance max`는
  가장 과최적화된 조합을 1등으로 뽑습니다
- `InpRiskPercent`, `InpDailyLossPct` 같은 **리스크 정책 변수는 최적화 대상이 아닙니다**

## 운용 전 체크리스트

1. **저스프레드 브로커 필수** — 스캘핑은 거래 빈도가 높아 스프레드가 기댓값을 직접 갉아먹습니다
2. **서버 시간 확인** — 세션 필터(`InpSessionStartHr/EndHr`)는 **브로커 서버 시간** 기준입니다. 한국 시간이 아닙니다
3. **데모 계좌에서 먼저 최소 2주** 돌려 대시보드의 기댓값·Profit Factor를 확인
4. **백테스트는 "실제 틱 기반(99%)" 데이터로** — MT4 기본 모델링 품질(90%)로는 스캘핑 결과를 신뢰하기 어렵습니다
5. 고임팩트 뉴스(FOMC, CPI, NFP) 시간대는 수동으로 `InpEnableTrading=false` 처리 권장

## 알려진 제약

- **뉴스 필터 미구현** — MT4 내장 경제지표 데이터로는 EA에서 안정적으로 읽을 수 없습니다.
  현재는 세션 필터 + 스프레드 확대 감지로 간접 대응합니다.
- **부분청산 티켓 승계** — MT4는 부분청산 시 잔여분에 새 티켓을 부여하고 코멘트를 `from #원본티켓`으로
  바꿉니다. EA는 이 규칙으로 잔여분을 추적하는데, 이를 따르지 않는 일부 브로커에서는
  재시작 직후 한정으로 추적이 끊길 수 있습니다.
- **MDD 기준** — 청산된 거래의 손익 곡선 기준이며, 미실현 평가손익의 일중 낙폭은 포함하지 않습니다.
